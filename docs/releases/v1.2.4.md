# Kingdom v1.2.4

This candidate adds plain-language work programmes in Tasks. Owners can save
outcomes in sections, select a configured planning model, review an exact proposed
mission, and let the existing service-owned backlog run reviewed work. Closing
the browser does not stop service planning or backlog review. Planning and global
execution have separate controls; automatic planning never approves missions or
grants tools. Explicit no-mission planning retries stop after three starts.

Each section needs its own reviewed project-test command, distinct from component
acceptance commands, before later sections can run. Acceptance binds the exact
programme, project, declared revision, mission version and step to actual retained
process receipts and a nonempty passing test summary. Changed evidence invalidates
dependent completion. Interrupted planning/binding is retained for review, not
replayed. Existing bounded function repair remains limited to its fixed profile;
arbitrary project commands execute once and are not automatically repaired.

Paired Knights can report bounded signed recent-work metadata and running versus
startup-enabled services. Stale, missing and revoked reports remain unavailable,
not zero work. Prompts, transcripts and command arguments are not included in
peer job summaries. Linux user services and Windows services are scoped
observations; arbitrary desktop startup programs and host/container management
remain unsupported unless a separate approved adapter exists. Observation grants
no management authority. An unused graph dependency and its Git fetch requirement
were removed from frontend installation.

The implementation source passed 1,088 local backend tests with 8 skips, 25
frontend contract tests and a production build before this synchronized version
preparation. Tests include real SQLite state, HTTP workflow, governed process
execution and receipts. Planner stubs test control flow only. Final exact-version
platform CI, live acceptance, artifact checks and uploaded-download verification
remain mandatory release gates; this file does not establish publication.

The source revision is an owner declaration, not an attestation of the checkout
used by a command. A separate command does not itself prove integration coverage;
the reviewer must inspect the suite. These changes do not establish reliable
general autonomous repository coding, autonomous skill installation, completed
owner backlog, universal fleet rollout, Boss/council agents or a Jules adapter.
Existing runtime, L4/L5 selection and actual tool/OS permissions still apply.
Native Windows/macOS signing and macOS notarization remain separate work.
