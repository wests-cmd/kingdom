# Kingdom v1.2.8

## Changes

- **Home is clearer for first-time users.** The default Easy interface shows **Needs your attention**, **Working now**, and **Recently finished**, with concise summaries, recorded status, and optional technical details. Advanced mode retains deeper orchestration views.
- **Task history and completion evidence.** A read-only, owner-authenticated task timeline uses persisted event IDs/types/timestamps, and a separate "What changed?" panel lists only eligible verified tool/artifact receipts. Missing evidence is stated explicitly; generated model text is not independent proof of actions.
- **Computer and AI-model visibility.** On-demand system health shows measured host-wide capacity, reported remote-computer inventory, and configured model profiles. Optional read-only provider checks distinguish a responding Ollama service from merely configured external endpoints.
- **In-app notifications.** Owner-only notifications read bounded, persisted event records for relevant task, approval and runtime events, without exposing raw event payloads or task prompts. Viewed state is per open page, not synchronized push delivery.
- **Mesh revocation hardening.** SQLite node registry, signed-RPC heartbeat, and degraded/stale health transitions now recheck current persisted approval state rather than rewriting old whole-record snapshots; late or concurrent health updates cannot restore a revoked or quarantined node. The signed RPC path also preserves validated inventory and load observations in one atomic transaction without changing grants or pinned identity. Three-computer mesh failures expose sanitized state/generation summaries for debugging.

## Limits and acceptance still open

- Real devices have not completed all eight [security commissioning gates](https://github.com/wests-cmd/kingdom/issues/172). Automated mesh tests are not a full multi-network or hostile-device revocation certification.
- The previous intermittent revocation propagation timeout has a plausible stale-write race fix and regression coverage; a passing run does not establish every distributed recovery edge case. Do not relax live revocation, owner approvals or fail-closed RPC.
- Desktop installers are unsigned; the Intel Mac installer is not notarized. Apple Silicon, Android APK and iOS IPA are **not published native release artifacts**. Mobile source release identity can match v1.2.8 without establishing app-store readiness or downloadable phone packages.
- In-app notices are not OS push/email/SMS; host RAM numbers are whole-host snapshots, not Kingdom process RAM. Connection states, model answers and task statuses are not proof of external outcomes.
- No blanket autonomous coding, remote desktop input, model-weight sharing, arbitrary intercomputer file access, or automatic deployment to paired Knights is implied. Installs on Laptop 2, DT1 and other physical computers remain separate validation.
