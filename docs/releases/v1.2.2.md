# Kingdom v1.2.2

This release candidate brings the distributed-work changes into the next versioned build: verified worker activity, distinct Knight/Apprentice labels, saved coordination maps, larger bounded missions, measured signed capacity, and isolated reconnecting private links.

Nodes & Cluster now reports installed releases against an owner-selected target. Newly connected approved Knights are compared automatically when their signed reports arrive. Unknown and offline computers do not count as updated. Actual installation still requires the computer's configured updater, verified artifact and existing permissions; pairing does not grant update authority.

Frozen builds carry explicit build-input metadata. This differs from observing source files on a running source installation and does not prove an installer signature. Installation and device acceptance evidence must accompany downloadable native builds. Unsigned packages must be labeled as such.

Coordination map edits currently organize reporting relationships; they do not change mission placement or grants. General autonomous coding, screen-control reliability and optional hardware integrations remain separately tracked acceptance work. The TwinDesk-inspired onboarding redesign is queued, not included as a completed feature.

Automated repository tests are scoped to `tests/`; generated agent workspaces are not collected as trusted repository tests.
