# Kingdom v1.2.7

## Changes

- Replace the production Python base image's inherited pip 25.0.1 with pip 26.3
  before installing runtime dependencies. An audit of the actual 1.2.6 container
  inventory found advisories that native-installer testing did not cover.
- Run the existing installed-package compromise check and OSV dependency audit
  in the final Docker image. The build fails if either check fails; source
  manifest validation remains before package installation.
- Synchronize the backend, desktop, web and mobile release identity at 1.2.7.

## Validation

- The old container's inventory audit reproduces the failure for pip 25.0.1.
  The repaired image must pass the same audit, copied-state health checks and
  rollback rehearsal before hardware activation.
- Native publication retains the exact-source build, installer and artifact
  verification gates. Earlier 1.2.6 acceptance is baseline evidence only.

## Limits

- Advisory checks report the queried inventory at build time, not a permanent
  security guarantee. Network failures also prevent successful image auditing.
- This changes packaging and release identity, not approval policy, worker
  grants, model qualification or the authority to execute generated code.
- Hardware updates preserve identities, credentials, state and known-good
  rollback versions. Phone distribution and OS disk replacement are separate.
