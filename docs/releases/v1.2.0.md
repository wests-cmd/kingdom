Kingdom v1TAS v1.2.0 adds a mission workspace, five active autonomy levels and separate Pause control.

Describe the whole objective in the larger task editor, attach ZIP, PDF, JPG/PNG/WebP, text or source files, and request a mission plan. Review, edit, approve or cancel that plan. Plans can create workspace files, run approved commands, verify results and produce a downloadable source ZIP. Failed command tests stop delivery. At levels 4 and 5, a plan can explicitly permit bounded repairs to one named source file; the test command stays fixed and each execution still requires approval. Missing model connections produce a blocked draft rather than a false completion.

Model connections support installed Ollama and OpenAI-compatible standard, custom, fine-tuned and abliterated models. Keys are encrypted locally and are never returned by the configuration API. These choices do not grant permissions, train weights or download models. Vision needs a compatible configured model; PDF extraction does not perform OCR. Original attachments are compressed, deduplicated and hash-checked; context selection retains source offsets. This is context retention, not model training.

Computer permissions are assigned explicitly to Knight Apprentices. Files stay within the workspace. Processes run on the host, not in an OS sandbox, and require exact human approval. Windows desktop input targets an exact foreground window and also requires approval; a receipt proves input was sent, not that the application achieved the objective. Linux/macOS native input and browser DOM automation are not supplied. Desktop capture needs an interactive session.

Knights are computers, Knight Apprentices are agents/bots on computers, the Commander controls approved groups, and a Knight Captain can assign supported work only inside its group. Level 5 can offload bounded text/syntax analysis to approved healthy computers with fresh capacity evidence. Arbitrary model inference and host control are not automatically distributed.

Compatible UI-only updates have a separate small ZIP with file hashes and explicit backend compatibility. Activation changes the interface on refresh without restarting the backend; rollback retains the previous selection and old assets remain available to open pages. Backend/native updates still require the matching installer and a restart. UI package discovery uses the published GitHub asset checksum; it does not accept arbitrary update URLs.

The tested automation handover remains available. An existing worker is replaced only after reviewed source, regression checks and exact-revision approval; retained progress and the original runner support recovery. The Laptop 2 workshop follows its configured two new skills, one refinement and one Kingdom review schedule; this does not certify a full day before it has elapsed.

Release assets include only successful native builds: Linux x86_64 AppImage/DEB, Windows x86_64 NSIS, macOS Intel DMG, platform backend binaries, evidence/screenshots, release manifest, checksums and the UI component. Windows and macOS builds are unsigned; macOS is not notarized. Apple Silicon native, iOS distribution and new Android distribution artifacts are not claimed by this desktop release.

Live brokerage connections, market data, order placement and money transfers remain unsupported. Kingdom can plan and generate trading-related software, but generated code is not evidence of a working broker integration or profitable strategy. Credentials must be configured in the relevant supported integration; they must not be pasted into task prompts or generated code.
