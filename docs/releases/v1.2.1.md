Kingdom v1TAS v1.2.1 adds owner-controlled Windows desktop updates in Settings. Check for a published stable release, download its checksum-verified installer, then choose Update and restart. The installer replaces the application files in their existing directory; profiles, tasks, settings, secrets and model connections remain in the existing per-user data folder. A native confirmation precedes shutdown. The backend stops cleanly before the helper installs and reopens Kingdom. Downloads can be kept until later; integrity is checked again before installation and by the helper. Failed attempts are reported on reopening, and retained data is not removed. Successful installer downloads are removed to save space.

This uses the full Windows installer internally and requires a brief restart; it is not a delta download or a hot backend update. macOS and Linux still use their native installer/package workflows. Compatible UI-only changes use the small component updater without restarting the backend. Windows/macOS installers remain unsigned and macOS is not notarized. SHA-256 verifies release-byte integrity; it is not publisher code signing.

Audit logging now recursively redacts nested dictionaries and iterable containers, including HTTP header pairs, normalizes non-string keys before JSON serialization, and safely handles cyclic/deep metadata. Regression tests exercise persisted audit records. This corrects the incomplete changes proposed in PR #120; generated old release notes are not included.

The v1.2.0 mission workspace and its documented limitations remain: five active autonomy levels plus Pause, inspected attachments, installed model profiles, exact approvals for host/Windows control, bounded repairs and supported analysis offload. ARM/native mobile installers, OCR, model training, browser DOM automation, Linux/macOS native input and live brokerage execution are not supplied.

Only verified native x86_64 assets are published: Linux AppImage/DEB, Windows NSIS and macOS Intel DMG, backend binaries, UI component, checksums, manifests, platform evidence and screenshots. Consult the attached evidence for exact acceptance checks; it is not exhaustive external-application or hardware certification.
