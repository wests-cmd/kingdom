# Kingdom v1.2.3

Kingdom's work list retains requested outcomes, dependencies, reviewed mission
versions and verification receipts. Its lifecycle runner reviews the list without
an open browser. Notes remain `needs_planning` until an executable reviewed
mission is attached. Automatic selection additionally requires explicit enabling,
a running runtime and autonomy level 4 or 5. Model text cannot complete an item.
Current source and retained evidence are rechecked before accepting completion.

A native mission can generate, write, read and check a small integer function,
then repair it within the existing budget against the same immutable case profile.
The first profile checks `bounded_batch_size` against 26 fixed cases. Its finite
arithmetic AST interpreter has source, structure, integer and evaluation budgets;
it never executes generated Python or invokes a process. It does not certify
arbitrary CPython tests or general repository coding. Existing syntax checks
retain their narrower meaning. Repository tests cover first-pass and repair
paths with real governed execution receipts; providers are fixtures only in tests.

Restart recovery retains mission and task identities. A pure bounded check can
resume safely; uncertain model, write, process or desktop effects remain reviewable.
Outstanding backlog leases are reconciled automatically only with proof that
the prior controller stopped and that retained operations meet recovery rules.
There is no lease-expiry replay or automatic permission expansion.

Release automation reads the canonical version instead of hardcoding a tag.
Version preparation is dry-run by default, preserves store build numbers and
requires explicit application and reviewed release notes. Exact-source,
three-platform, immutable-tag, checksum and uploaded-download gates remain.

The work list is visible in Tasks and Automations. Native Windows and Intel
macOS packages remain unsigned; macOS is not notarized. Broader fleet, storage,
graphical OS installation and signing acceptance remain separate work. Source
changes do not mean every connected device has updated. See
[release preparation](../RELEASE_PROCESS.md) for the publication gates.
